v0.2.10 18 Oct 2026

  • The two files g model overwrites whole, db/queries/<table>.sql and app/models/<table>.go, now open with a comment saying so and naming the sibling file for your own code: <table>_extra.sql for a hand-written query, <table>_extra.go for a store method. See Hand-written code beside generated code.
  • Existing apps: the comment appears the next time g model rewrites a table's files. A query you added inside a generated .sql file should move to <table>_extra.sql before then.

v0.2.9 18 Oct 2026

  • New apps get bigint ids by default (an auto-incrementing bigserial), as Rails does, instead of uuid. bogie new NAME --id=uuid keeps uuids. The choice is app-wide, recorded in bogie.toml, and every later generator and app:update follows it. See Id schemes.
  • Existing apps have no id line in bogie.toml, which reads as uuid, so they stay on uuid and nothing changes. Leave that line out rather than adding id = "bigint".
  • A scaffolded Update now loads the record first and reuses its id, instead of building the id from the URL string. New scaffolds get it; an existing one keeps working under uuid as it is.
  • The generated routes_test.go no longer fails golangci-lint (a comment read as a malformed go:embed directive).

v0.2.8 17 Oct 2026

  • An app's own public/index.html now answers at /, in every environment. Before, / always fell through to the development welcome page or the 404. See Static files and error pages.
  • The generated 404.html and 500.html show the Bogie mascot, styled like the welcome page.
  • Existing apps get both through bogie app:update.

v0.2.7 17 Oct 2026

  • New public/ folder, embedded in the binary: a request no route answers is tried against a file there, then the development welcome page, then public/404.html. A panicking handler gets public/500.html. To serve a favicon or robots.txt, drop it in public/ and widen the go:embed line in public/public.go.
  • Hand-written store methods now go in a sibling file, app/models/<table>_extra.go, because g model rewrites app/models/<table>.go whole. See Models and migrations.
  • Existing apps get public/ through bogie app:update.

v0.2.6 17 Oct 2026 Breaking

Breaking Seeds are no longer goose SQL files with a version table. db:seed:rollback, db seed-down, make db-seed-down and make g_seed_* are gone. What to do: commit, port any existing seed SQL into db/seeds/*.go by hand, then run bogie app:update for the new runner; it moves the layout but does not translate seed content. Write each seed so a second run changes nothing. See Upgrading an app.

  • Seeds are plain Go: bogie g seed NAME writes db/seeds/<name>.go and registers it; bogie db:seed runs every seed, every time, so each must be safe to run twice. bogie d seed NAME takes one out. See Seeds.

v0.2.5 16 Oct 2026

  • New bogie routes, like rails routes: every mounted route with its method, path and handler, read from the booted app. It prints in development only. Existing apps get it through bogie app:update.

v0.2.4 16 Oct 2026

  • A field with no type defaults to string, as in Rails: bogie g model comment title body:text.
  • string now becomes Postgres varchar instead of text, keeping the distinction Rails makes. Only new migrations are affected; existing ones keep whatever type they already say.

v0.2.3 13 Oct 2026 Breaking

Breaking The test environment now reads only <APP>_TEST_DATABASE_URL, never <APP>_DATABASE_URL, so tests and bin/ci can no longer empty a development database. What to do: a CI setup that points tests at a database through <APP>_DATABASE_URL must rename it to <APP>_TEST_DATABASE_URL. Existing apps get the fix through bogie app:update. See Upgrading an app.

  • A scaffolded PATCH changes only the fields sent; before, it blanked the rest. New scaffolds get it; an existing scaffolded Update needs the change by hand (the release notes show the few lines).
  • bogie server and bogie worker stop the app they started on SIGTERM.
  • bogie help lists the authentication generator; the request log shows path=/ for the root.
  • Docs: using your own Postgres without Docker (see Your own Postgres), a code of conduct and a security policy.

v0.2.2 6 Oct 2026

  • When the database cannot be reached, the error now says which of the common causes it is (nothing listening, credentials refused, or the database never created) and what to run, keeping the original error underneath.

v0.2.1 6 Oct 2026

  • bogie app:update adds the tool directives that newer templates pin, such as Air for live reload, so an older app reloads after updating without a manual go get -tool.

v0.2.0 6 Oct 2026

  • Live reload: in development bogie server and bogie worker run under Air, rebuilding and restarting on save. Production runs the compiled binary.
  • bogie g job works on an app made without --jobs, adding River first.
  • New apps need Go 1.26, pinned in the template (the tool itself builds with 1.25).

v0.1.0 3 Oct 2026

  • The first release: bogie new (with --jobs for River), the generators migration, model, scaffold, controller, service, job and authentication, bogie destroy, bogie doctor and bogie app:update.
  • Generated apps ship credentials, migrations, bin/ci, a Dockerfile and Kamal 2 config, a welcome page and AGENTS.md.
  • Installed with go install only; no Homebrew tap.

Older history, before the first tag, is in the commit log.
