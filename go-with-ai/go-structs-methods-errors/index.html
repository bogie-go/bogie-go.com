Chapter 4: Modeling Data and Handling Errors

In short: Chapter 4 gives Tracker a proper shape with a struct and methods, and makes it remember your expenses in a JSON file. Because saving to a file can fail, you also learn Go's error handling: returning errors, wrapping them with %w and never ignoring them.

Close Tracker, and your expenses are gone. Every run starts from the same four hard-coded amounts. A tracker that forgets everything isn’t much of a tracker.

In this chapter, Tracker learns to remember. You’ll give expenses a proper shape with a struct, which is the suggestion the AI kept making in Chapter 3. You’ll give Tracker methods that add, total, save and load expenses. And because saving to a file is the first thing in this book that can fail for reasons outside your code (a missing folder, a broken file), you’ll learn how Go handles errors.

The AI is your pair for this whole chapter. The book gives you the first part of the new code. Then you write the rest yourself, ask the AI for a review, and decide what to keep, using the same three questions as Chapter 3. It’s the same SURE loop, with more of it in your hands.

Mission

By the end of this chapter, you’ll have:

  • An Expense struct and a Tracker type with methods
  • Tracker saving your expenses to expenses.json and loading them on the next run
  • A command to add expenses: go run . add Food 350
  • Clear error messages for bad input, instead of crashes or silent mistakes
  • A commit with a Learned: line

Must know

  1. A struct groups named fields into one type. type Expense struct { Category string; Cents int } describes every expense. Fields that start with a capital letter are exported, and encoding/json only sees exported fields. (Chapter 5 covers exported names properly.)
  2. A method is a function attached to a type. func (tr *Tracker) Add(...) is a method on Tracker. You call it with a dot: tracker.Add("Food", 350).
  3. A pointer lets a function change the original instead of a copy. *Tracker means “a pointer to a Tracker,” and &x gives you a pointer to x. A method that changes its value needs a pointer receiver, (tr *Tracker). Otherwise it changes a copy, and the change disappears.
  4. Errors are values. A function that can fail returns an error as its last result. nil means it worked. You check every error: if err != nil { ... }.
  5. Wrap errors to add context. fmt.Errorf("save expenses: %w", err) adds what you were doing to the error. Later, errors.Is(err, target) can still look inside the wrapping. The %w is what makes that work.

The new code will live in a new file, tracker.go, so its tests go in a new file too. Create tracker_test.go next to main.go:

package main

import (
    "errors"
    "maps"
    "os"
    "path/filepath"
    "slices"
    "testing"
)

func TestTrackerAdd(t *testing.T) {
    tests := []struct {
        name     string
        category string
        cents    int
        wantErr  error
        wantLen  int
    }{
        {"valid", "Food", 350, nil, 1},
        {"zero", "Food", 0, ErrInvalidAmount, 0},
        {"negative", "Food", -100, ErrInvalidAmount, 0},
    }
    for _, tt := range tests {
        var tr Tracker
        err := tr.Add(tt.category, tt.cents)
        if !errors.Is(err, tt.wantErr) {
            t.Errorf("%s: Add() error = %v, want %v", tt.name, err, tt.wantErr)
        }
        if len(tr.expenses) != tt.wantLen {
            t.Errorf("%s: %d expenses after Add, want %d", tt.name, len(tr.expenses), tt.wantLen)
        }
    }
}

func TestTrackerTotals(t *testing.T) {
    tr := Tracker{expenses: []Expense{
        {Category: "Food", Cents: 350},
        {Category: "Transport", Cents: 1200},
        {Category: "Food", Cents: 99},
    }}
    got := tr.Totals()
    want := map[string]int{"Food": 449, "Transport": 1200}
    if !maps.Equal(got, want) {
        t.Errorf("Totals() = %v, want %v", got, want)
    }
}

func TestSaveAndLoad(t *testing.T) {
    path := filepath.Join(t.TempDir(), "expenses.json")
    saved := Tracker{expenses: []Expense{
        {Category: "Food", Cents: 350},
        {Category: "Fun", Cents: 1500},
    }}
    if err := saved.Save(path); err != nil {
        t.Fatalf("Save() error = %v", err)
    }
    loaded, err := Load(path)
    if err != nil {
        t.Fatalf("Load() error = %v", err)
    }
    if !slices.Equal(loaded.expenses, saved.expenses) {
        t.Errorf("loaded %v, want %v", loaded.expenses, saved.expenses)
    }
}

func TestLoadMissingFile(t *testing.T) {
    path := filepath.Join(t.TempDir(), "missing.json")
    tr, err := Load(path)
    if err != nil {
        t.Fatalf("Load() error = %v, want nil", err)
    }
    if len(tr.expenses) != 0 {
        t.Errorf("Load() has %d expenses, want 0", len(tr.expenses))
    }
}

func TestLoadBrokenFile(t *testing.T) {
    path := filepath.Join(t.TempDir(), "expenses.json")
    if err := os.WriteFile(path, []byte("not json"), 0o644); err != nil {
        t.Fatal(err)
    }
    if _, err := Load(path); err == nil {
        t.Error("Load() error = nil, want an error for a broken file")
    }
}

Three new testing tools appear here:

  • errors.Is(err, tt.wantErr) checks whether an error is, or wraps, a specific error. When wantErr is nil, it checks that there was no error at all.
  • t.TempDir() gives each test a fresh, empty folder that Go deletes afterwards, so tests never touch your real expenses.json.
  • t.Fatalf reports a failure and stops that test immediately. Use it when there’s no point going on: if Save failed, there’s nothing to Load.

Notice that TestTrackerTotals builds its Tracker directly with the expenses inside, instead of calling Add. That keeps it from ignoring Add’s errors, and ignoring errors is exactly what this chapter teaches you not to do.

Type the first part

Create tracker.go and type this:

package main

import (
    "errors"
    "fmt"
)

// Expense is one thing you spent money on.
type Expense struct {
    Category string `json:"category"`
    Cents    int    `json:"cents"`
}

// Tracker holds all your expenses.
type Tracker struct {
    expenses []Expense
}

// ErrInvalidAmount means an expense amount was zero or negative.
var ErrInvalidAmount = errors.New("amount must be more than zero")

// Add records one expense.
func (tr *Tracker) Add(category string, cents int) error {
    if cents <= 0 {
        return fmt.Errorf("add %q: %w", category, ErrInvalidAmount)
    }
    tr.expenses = append(tr.expenses, Expense{Category: category, Cents: cents})
    return nil
}

Things to notice:

  • The text after each field, like `json:"category"`, is a struct tag. It tells encoding/json to write the field as "category" in the file instead of "Category".
  • Expense{Category: category, Cents: cents} in Add builds an expense with named fields: each field’s name, a colon, then its value. You read or set a field with a dot: if e is an Expense, e.Category is its category, and e.Cents = 500 changes its amount.
  • Any field you leave out gets its zero value, the rule from Chapter 3: Expense{Category: "Food"} has Cents set to 0, and var e Expense has Category "" and Cents 0.
  • expenses starts with a lowercase letter, so it’s private to this package. Other code goes through Add and the other methods rather than touching the slice directly.
  • ErrInvalidAmount is a sentinel error: a named error that callers can check for with errors.Is. Add wraps it with the category, so the message says what went wrong and where.
  • Add returns nil when everything worked. Every path through a function that returns error ends with an error or nil.

Your turn: Totals, Save and Load

Add these to the end of tracker.go. Your tests say exactly what each must do.

func (tr *Tracker) Totals() map[string]int returns the total for each category. Loop over tr.expenses and add each expense’s Cents to its category in a new map. You did almost the same thing in Chapter 3.

func (tr *Tracker) Save(path string) error writes all expenses to a file:

  • json.MarshalIndent(tr.expenses, "", " ") turns the slice into JSON text, indented with two spaces. It returns the text and an error.
  • os.WriteFile(path, data, 0o644) writes the text to the file. 0o644 sets the file’s permissions: you can read and write it, and others can only read it.
  • Check both errors, and wrap each with fmt.Errorf("save expenses: %w", err).

func Load(path string) (*Tracker, error) is a plain function, not a method, because there’s no Tracker yet when you load one. It reads the file and returns a new Tracker:

  • os.ReadFile(path) returns the file’s contents and an error.
  • If the file doesn’t exist, errors.Is(err, os.ErrNotExist) is true. That’s not a failure: return an empty &Tracker{} and nil.
  • Any other error: return nil and the error wrapped with "load expenses: %w".
  • json.Unmarshal(data, &tr.expenses) fills the slice from the JSON text. It needs a pointer (&) so it can change the slice. Check its error too.

You’ll need two more imports in tracker.go: "encoding/json" and "os". Then write, run go test ./..., read the errors, and repeat until you see ok. If you’re stuck, ask the AI to explain an error message, not to write the method.

Compare with the book’s version

Here’s one version that passes the tests. Yours may differ; that’s fine if your tests pass and you can explain every line.

// Totals returns the total in cents for each category.
func (tr *Tracker) Totals() map[string]int {
    totals := make(map[string]int)
    for _, e := range tr.expenses {
        totals[e.Category] += e.Cents
    }
    return totals
}

// Save writes all expenses to the JSON file at path.
func (tr *Tracker) Save(path string) error {
    data, err := json.MarshalIndent(tr.expenses, "", "  ")
    if err != nil {
        return fmt.Errorf("save expenses: %w", err)
    }
    if err := os.WriteFile(path, data, 0o644); err != nil {
        return fmt.Errorf("save expenses: %w", err)
    }
    return nil
}

// Load reads expenses from the JSON file at path.
// A missing file means there are no expenses yet.
func Load(path string) (*Tracker, error) {
    data, err := os.ReadFile(path)
    if errors.Is(err, os.ErrNotExist) {
        return &Tracker{}, nil
    }
    if err != nil {
        return nil, fmt.Errorf("load expenses: %w", err)
    }
    tr := &Tracker{}
    if err := json.Unmarshal(data, &tr.expenses); err != nil {
        return nil, fmt.Errorf("load expenses: %w", err)
    }
    return tr, nil
}

if err := os.WriteFile(...); err != nil is a common Go shape: the if runs a statement first, then checks the condition. The err it creates only exists inside that if.

Connect Tracker to main

The old map-based code is replaced, so remove it:

  • In main.go, delete the addExpense and totalsByCategory functions. Tracker does their jobs now.
  • In main_test.go, delete TestTotalsByCategory, and remove "maps" from its imports. Nothing else in that file uses maps, and Go refuses unused imports.

Then, in main.go, replace the import block and the whole main function with this:

import (
    "errors"
    "fmt"
    "os"
    "slices"
    "strconv"
)

const dataFile = "expenses.json"

func main() {
    if err := run(os.Args[1:]); err != nil {
        fmt.Fprintln(os.Stderr, "Error:", err)
        os.Exit(1)
    }
}

func run(args []string) error {
    tracker, err := Load(dataFile)
    if err != nil {
        return err
    }

    if len(args) == 0 {
        fmt.Println(welcome())
        totals := tracker.Totals()
        if len(totals) == 0 {
            fmt.Println("No expenses yet.")
        }
        for _, category := range sortedCategories(totals) {
            fmt.Println(describeCategory(totals, category))
        }
        return nil
    }

    if len(args) == 3 && args[0] == "add" {
        category := args[1]
        cents, err := strconv.Atoi(args[2])
        if err != nil {
            return fmt.Errorf("amount must be whole cents: %w", err)
        }
        if err := tracker.Add(category, cents); err != nil {
            return err
        }
        if err := tracker.Save(dataFile); err != nil {
            return err
        }
        fmt.Println("Added", formatExpense(category, cents))
        return nil
    }

    return errors.New("usage: go run . [add CATEGORY CENTS]")
}

This is the pattern for every error in a Go program. run does the work and returns any error it meets, and only main decides what to do about it: print it and stop. os.Args holds the words typed after the program’s name, strconv.Atoi turns text like "350" into the number 350, and fmt.Fprintln(os.Stderr, ...) prints to the terminal’s error output.

Break it on purpose

Break 1: lose the pointer. In tracker.go, change func (tr *Tracker) Add to func (tr Tracker) Add, removing one *. It compiles, and go vet stays silent. Now run go test ./...:

--- FAIL: TestTrackerAdd (0.00s)

Without the pointer, Add appends to a copy of the Tracker, and the copy disappears when Add returns. No error, no crash, just a lost expense. Only the test caught it, because it checks the count. Put the * back.

Break 2: %v instead of %w. In Add, change %w to %v and run go test ./...:

--- FAIL: TestTrackerAdd (0.00s)
    tracker_test.go:28: zero: Add() error = add "Food": amount must be more than zero, want amount must be more than zero

Where AI gets Go wrong: errors and data

  • Ignoring errors. AI-written code sometimes throws errors away with _ (data, _ := os.ReadFile(path)) or doesn’t look at them at all (os.WriteFile(path, data, 0o644) on a line by itself). It compiles, go vet doesn’t complain, and the program carries on with bad data. The Practice exercise is all about spotting this.
  • %v where %w belongs. As Break 2 showed, the message looks the same, and errors.Is silently stops working.
  • Comparing error text. Code like if err.Error() == "amount must be more than zero" breaks the moment anyone wraps the error or rewords the message. Use errors.Is.
  • Lowercase fields with JSON tags. A field like category string `json:"category"` is unexported, so encoding/json skips it without any error. The file just lacks that field. go vet catches this one: struct field category has json tag but is not exported.
  • Stopping the program from deep inside. log.Fatal or panic inside a function like Load takes the decision away from main. Return the error instead.

Practice (optional)

Here’s a short program an AI might write to back up expenses. It compiles, go vet is silent, and it even prints a cheerful message. It also has four ignored errors. Save it as ignored.go in your practice folder and run it with go run ignored.go:

package main

import (
    "encoding/json"
    "fmt"
    "os"
)

type Expense struct {
    Category string `json:"category"`
    Cents    int    `json:"cents"`
}

func save(path string, expenses []Expense) {
    data, _ := json.MarshalIndent(expenses, "", "  ")
    os.WriteFile(path, data, 0o644)
}

func load(path string) []Expense {
    data, _ := os.ReadFile(path)
    var expenses []Expense
    json.Unmarshal(data, &expenses)
    return expenses
}

func main() {
    expenses := []Expense{
        {Category: "Food", Cents: 350},
        {Category: "Fun", Cents: 1500},
    }
    save("backup/expenses.json", expenses)
    fmt.Println("Saved", len(expenses), "expenses")

    loaded := load("backup/expenses.json")
    fmt.Println("Loaded", len(loaded), "expenses")
}

It prints:

Saved 2 expenses
Loaded 0 expenses

Two expenses saved, zero loaded, and no error anywhere. The backup folder doesn’t exist, so the save failed, but nothing told you.
