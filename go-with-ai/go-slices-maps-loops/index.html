Chapter 3: Lists, Lookups and Loops

In short: Chapter 3 teaches Go's slices, maps and its one loop keyword, for. Tracker learns to total expenses by category in a stable order, you see why Go maps have no order, and the AI switches from tutor to pair: you write the code and it reviews it.

So far, Tracker knows about one coffee and a hard-coded list of three amounts. Real spending doesn’t work like that. You buy food twice in one day, take a taxi, see a film, and at the end of the month you want to know: where did the money go?

In this chapter, Tracker learns to record expenses by category and total each one. To do that, you’ll go deeper into the two tools Go gives you for groups of values: slices (lists) and maps (lookups). You’ll also meet loops and if properly, and a Go idea that quietly explains a lot of surprises: zero values.

It’s the same SURE loop as before. But halfway through this chapter, something changes.

From tutor to pair

Until now, the AI has been your tutor: it explained, and you typed code from the book. In this chapter, you’ll do both jobs in turn:

  • First half: tutor. The AI explains maps and slices, and you type two functions from the book.
  • Second half: pair. You write two functions yourself, from the tests. Then you ask the AI to review your code, and you decide which of its suggestions to keep.

That last part is the new skill. A review is a list of suggestions, not orders. Some will be good, some will be fine but unnecessary, and some will be wrong. Deciding which is which is how you learn, and it’s a skill you’ll use for the rest of your career.

Mission

By the end of this chapter, you’ll have:

  • A way to add expenses, each with a category and an amount in cents
  • Totals for each category, printed in a stable order
  • A clear message for a category with no expenses
  • Two functions you wrote yourself, reviewed by the AI
  • A commit with a Learned: line

Must know

  1. A slice is a list that can grow. append adds items and returns the new slice, so you always write s = append(s, item). len(s) gives the number of items.
  2. A map looks up a value by its key. In map[string]int, the keys are strings and the values are ints. You create one with make(map[string]int).
  3. Every type has a zero value. It’s what a variable holds before you give it anything: 0 for numbers, "" for strings, false for bool, and nil for slices and maps. Looking up a missing map key gives you the zero value, not an error.
  4. A nil slice is ready to use; a nil map is not. You can append to a nil slice and take its len. You can read from a nil map, but writing to one crashes your program. Always create maps with make before writing to them.
  5. Map order is random, on purpose. When you loop over a map, Go may give you the keys in a different order each run. When order matters, collect the keys into a slice and sort it.

func TestDescribeCategory(t *testing.T) {
    totals := map[string]int{"Food": 449, "Gifts": 0}
    tests := []struct {
        category string
        want     string
    }{
        {"Food", "Food: 4.49"},
        {"Gifts", "Gifts: 0.00"},
        {"Travel", "Travel: no expenses"},
    }
    for _, tt := range tests {
        got := describeCategory(totals, tt.category)
        if got != tt.want {

        }
    }
}

Use the AI

First half: the AI as tutor

Start your assistant in the tracker folder and ask:

Explain Go maps and slices to a beginner. What does
map[string][]int mean? What happens when I look up a key that
isn't in a map? Don't write code for my project.

Follow up on anything unclear, especially what expenses[category] gives you when that category has no expenses yet. Then type these two functions at the end of main.go:

func addExpense(expenses map[string][]int, category string, cents int) {
    expenses[category] = append(expenses[category], cents)
}

func totalsByCategory(expenses map[string][]int) map[string]int {
    totals := make(map[string]int)
    for category, amounts := range expenses {
        totals[category] = total(amounts)
    }
    return totals
}

addExpense is short, but it uses three ideas at once. The first time you add a Food expense, expenses["Food"] doesn’t exist yet, so the lookup gives the zero value for a slice: nil. Appending to nil works fine and gives a slice with one item. Then the result is stored back under "Food". No special case is needed for “first expense in a category.”

totalsByCategory loops over a map. With a map, range gives you each key and its value. And it reuses total from Chapter 2, so code you’ve already tested does the adding.

Go has only one loop keyword, for, and it comes in three shapes:

  • for category, amounts := range expenses visits every item in a map or slice. You’ll use this one most.
  • for i := 0; i < 3; i++ counts: start at 0, keep going while i < 3, add 1 each time.
  • for sum < 1000 repeats while a condition is true, like while in other languages.

If the AI ever writes while, it’s thinking of another language. Go doesn’t have it. Ask your tutor for a tiny example of each shape if you want to see them run.

Second half: the AI as pair

Now the switch. First, tell your AI about its new job. Add this line to AGENTS.md:

When I ask for a review: list problems and suggestions with a one-line reason each, and don't rewrite my code.

Your first rule, “do not write or change code unless I ask,” still holds. The new rule says how to review.

Now write the last two functions yourself, at the end of main.go. Your tests tell you exactly what each one must do.

sortedCategories(totals map[string]int) []string returns the keys of totals, sorted by name. You’ll need:

  • a for ... range loop over the map (you only need the keys: for category := range totals)
  • append to collect each key into a slice
  • slices.Sort to sort the slice, which means adding "slices" to the imports in main.go

describeCategory(totals map[string]int, category string) string returns "Food: 4.49" for a category in the map and "Travel: no expenses" for one that isn’t. You’ll need:

  • the comma-ok lookup, cents, ok := totals[category], where ok is true only if the key is in the map
  • an if to handle the missing case
  • formatExpense from Chapter 2, which already formats "Food: 4.49"

To add "slices", change the top of main.go to:

import (
    "fmt"
    "slices"
)

Write, run go test ./..., read the errors, and repeat until you see ok. If you’re stuck, ask your AI to explain an error message or a concept, not to write the function.

Ask for a review

When your tests pass, ask for a review:

Review my sortedCategories and describeCategory functions in
main.go. List problems and suggestions, each with a one-line
reason. Don't rewrite my code; I'll decide what to change.

Every review is different, so the book can’t show you yours. But you’ll decide on each suggestion with the same three questions:

  1. Do I understand it? If you can’t explain the suggestion, you can’t keep it. That’s the one rule. Ask about it, or skip it for now.
  2. Does it fit this project? It must follow your rules: AGENTS.md (Go 1.27, standard library only) and the book’s Must know points, like money in cents.
  3. Do the tests still pass? Make one change at a time and run go test ./... after each.

Here are example suggestions (not real AI output) and how the three questions sort them:

Suggestion Keep? Why
Create the slice with make([]string, 0, len(totals)) so it has room for every key Your call It saves a little work as the slice grows. Keep it if you can explain what the len(totals) part does; otherwise skip it for now.
Add a comment above each function Keep Cheap, and it forces you to say what the function does, which is the Explain step in miniature.
Use a struct for expenses instead of a map of slices Skip for now Probably right, and Chapter 4 does exactly that. Changing it now would mean code you can’t explain yet.
Use slices.Sorted(maps.Keys(totals)) Skip for now It works in Go 1.27, but it uses iterators, which this book doesn’t cover. If you can’t explain it, don’t keep it.

Compare with the book’s version

Here’s one version that passes the tests. Yours may look different, and that’s fine if your tests pass and you can explain every line:

func sortedCategories(totals map[string]int) []string {
    var categories []string
    for category := range totals {
        categories = append(categories, category)
    }
    slices.Sort(categories)
    return categories
}

func describeCategory(totals map[string]int, category string) string {
    cents, ok := totals[category]
    if !ok {
        return category + ": no expenses"
    }
    return formatExpense(category, cents)
}

var categories []string starts as a nil slice, the zero value, and append grows it. That’s Must know #4 doing real work.

Print the report

Last, make main print the report from SPEC.md. Replace main with:

func main() {
    fmt.Println(welcome())

    expenses := make(map[string][]int)
    addExpense(expenses, "Food", 350)
    addExpense(expenses, "Transport", 1200)
    addExpense(expenses, "Food", 99)
    addExpense(expenses, "Fun", 1500)

    totals := totalsByCategory(expenses)

Break 1: a nil map. In main, change expenses := make(map[string][]int) to var expenses map[string][]int, and run go run .:

goroutine 1 [running]:

    /home/you/tracker/main.go:50

Your folder path and the +0x8c part will differ. This is a panic: Go stopped your program while it was running. The compiler couldn’t catch it, because the code is valid Go. The first line says what went wrong, and the list below it shows where: addExpense, called from main. That’s Must know #4: a var map is nil, and writing to it crashes. Put make back.

Break 2: forget the ok. In describeCategory, replace the first four lines of the body with cents := totals[category], and run go test ./...:

Without ok, a missing category looks exactly like a category that totals zero, because a missing key gives the zero value. Your Travel row caught it. The Gifts row, which still passes, shows why: zero and missing look the same without ok. Put the ok check back.

Check it yourself

Be SURE you can explain it, including every suggestion you kept.

Where AI gets Go wrong: lists and maps

  • Counting on map order. AI-written code sometimes loops over a map and expects a fixed order. It can pass a test several times and then fail at random. Sort the keys.

  • Comparing maps or slices with == or !=. In TestTotalsByCategory, change !maps.Equal(got, want) to got != want and run go test ./...:

    # tracker [tracker.test]
./main_test.go:4:2: "maps" imported and not used
./main_test.go:70:5: invalid operation: got != want (map can only be compared to nil)
FAIL    tracker [build failed]
FAIL

    Go doesn’t compare whole maps or slices with ==. Use maps.Equal and slices.Equal. Change it back.

  • Dropping the result of append. append returns the new slice. Code that writes append(categories, category) without categories = doesn’t compile: append(categories, category) (value of type []string) is not used.

  • Old package paths. golang.org/x/exp/slices and golang.org/x/exp/maps were where these packages lived before Go 1.21. AI trained on older code may still suggest them. If you paste such code, go test ./... stops with:

    main.go:5:2: no required module provides package golang.org/x/exp/slices; to add it:
    go get golang.org/x/exp/slices

    Don’t run that go get. Change the import to slices.

  • Old code that treats maps.Keys as a slice. Code written for the old golang.org/x/exp/maps does keys := maps.Keys(m) and then slices.Sort(keys). With the standard maps package, maps.Keys returns an iterator, not a slice, so Go stops with in call to slices.Sort, S (type iter.Seq[string]) does not satisfy ~[]E. Collect the keys with a loop, as sortedCategories does.
